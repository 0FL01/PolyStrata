# Venture decode: price a committed row

Tideglass Inkling 2 Mini, one RX 6700 XT (`gfx1031`, 12 GiB), Ryzen 7 5700X, 8 expert workers, HIP Release. Starting point: `1798843d`, including the transaction from `384251dc`. The installed W1 and the starting epoch worker are **different binaries**. W1 with a loaded drafter and the same residency policy is the verifier correctness control; W1 without a drafter at the same physical reserve is the product control.

**What to use.** For matched long-history decode throughput, start with dense Q8 global history, exact compact SWA, Q4_0 DFlash2, E4/K3, and compare `STRATA_EXPERT_LAYER_JOIN=1` (`f90a3430`) against the synchronous join. For long *fresh* prompt latency test `STRATA_DFLASH2_SKIP_COLD=1` (`6e8bd737`). Both are off by default. Neither is a recommendation to replace the installed interactive W1. The experiments below distinguish RAM/VRAM savings, faster individual kernels, faster generation of the same IDs and faster answers to a graded task.

## Where the time goes

The controlled greedy test restored 65,792 rows, evaluated 2,048 more to warm the Q4_0 drafter, and emitted 49 IDs (48 fed). Both arms used stable prefill, dense Q8 with compact SWA, the same profile seed and 5,200 MiB combined expert/KV cap. Epoch 4 with 64 swaps: **30.35 → 41.58 IDs/s** loaded W1 → K3. Wire ID-gap p90 **45.70 → 98.35 ms**. Both ended with the same 49 IDs, profile and **13,318 / 18,816** routed picks on GPU. No placement repair; 48 of 51 verifier rows kept. The last emitted ID need not be fed. The cap and staging are controls, not service settings.

On a separate K3 kernel trace, 13 rounds used **215.4 ms** of generic resident Q4_0 expert slots, **146.2 ms** of target Q8 attention leaves, **108.1 ms** of native multi-column GEMV and **29.9 ms** of Q6 head kernels (target and draft together). Median summed draft kernels per ask: **6.12 ms**; shared Q6 head 1.11, FFN projections 1.58 and draft attention scores/values 0.65/1.61 ms. These are dispatch durations, not mutually exclusive wall-time savings. In a separate timed worker the new admission join took **141.24 ms for 567 copies**, over 12 boundaries. The RAM packer, PCIe transfer, event waits and publication are included in the join; it is not isolated link time.

The same accounting on a real three-turn coding task at 64K, sampled seed 42, changes the ranking. Below, `charged rows` counts only speculative rounds, excluding separate W1 calls. Verification time ends when target logits are available. Round time also includes host sampling, keeping rows and appending committed taps. The CPU timer overlaps GPU work. Native TTFT and time to correct start **after RESTORE**. Decode IDs/s divides emitted IDs (including the first) by the engine's `DONE` decode time; it is not the inverse of cost per fed row.

## Admission by bytes

One incoming expert costs **4,478,976 B** (three Q4_0 matrices), or **4,644,864 B** with the Q4_1 down. Admission unpublishes a same-size victim; it doesn't buy another slot. One scratch worker retained the recency half-life, size classes and `incoming >= 2 × victim + 2` threshold. It budgeted actual gate/up/down transfer bytes (including refills). The priced variant compared estimated net CPU time saved per byte among eligible pairs. It used an 80 µs marginal miss proxy, a 32-row discounted forecast and a fixed copy price. The price is an input, not an online measurement: W1 and verifier can make identical decisions from committed history.

In this ledger run the cheap unpriced cap beat both modeled prices. The highest price avoided 2.0 GiB of transfer but sent 2,578 more picks to CPU. Do not minimize wait or maximize hit rate separately. At 0 and 64 µs/MiB, matched W1/K3 pairs also matched ordered admission fingerprints at every boundary, final profile, route counts and IDs. Separate A/B work on publication keeps ranking and membership fixed instead of charging fewer admissions.

**When does a miss actually stall verification?** A separate instrumented run put a HIP event after the last resident expert operation and a second on the same stream when `cpu_experts` returned. Elapsed time was read after the next router wait, not by inserting a new blocking sync. This measures an uncovered interval on the target stream, not all CPU compute or a hardware idle counter. Across the visits with misses, W4 summed to **519.2 ms** in the host call, **333.1 ms** between device timestamps (569 recorded visits); the W3 round added **35.5 / 24.1 ms**. On W4, with 1–4 host picks out of 32 the median gap stayed at ~5 µs. At 6/8/12/16 host picks it was **147/442/754/1,334 µs**. A hit at a CPU-limited layer is worth more than a hit where the GPU is already slower. Correlated picks, weight reuse and placement affect these conditional medians: they are not a per-miss invoice.

On the same 48-fed-row suffix, E4 W1 recorded 2,006 host-using visits and **503.1 ms** uncovered (288.9 ms in the repeated core). E8 K7/32 recorded 287 and **353.5 ms** (194.6 ms in the core). A K3 A/B with/without the existing CPU Q4 unpack-sharing path overlapped in engine throughput: **41.16 / 41.01 IDs/s** enabled vs **42.97 / 37.39** disabled; all 49 IDs and route counts matched. No new default follows.

**Overlap without changing membership.** A fixed-epoch scratch follower queued the same complete batch in physical first-visit order, then joined each layer's last DMA event before reading its first expert slot. The 64K BAAB, same executable, slots, 567 trades and 49 greedy IDs: sync **40.98 / 41.27 IDs/s**, layer join **42.76 / 45.53**; p90 **98.89 / 98.13** vs **93.68 / 87.62 ms**. Across the target softcaps the baseline had **101.06 ms** of recorded H2D, zero overlapping dispatches. The layer join had **101.09 ms**, of which **44.43 ms overlapped**. This is a measured overlap, not a claim to have hidden the full synchronous join. Simply submitting the same transfers before the proposal and waiting as usual before verification gave overlapping wings (43.60 / 39.55 vs 43.10 / 43.19 IDs/s). Direct registered-source DMA on the earlier layer-join prototype likewise did not consistently improve the engine.

On the 64K **sampled** coding control the clean layer join and synchronous worker made the same two tool calls, emitted the same 517 IDs and kept the same 142,999/199,296 picks on GPU. Sync → layer join: **20.88 → 20.58 s** to correct, **41.03 → 42.00 IDs/s**, **83.31 → 80.61 ms** ID-gap p90. The parity worker matched synchronous loaded W1 in all **47** settled boundaries and 38,411,136 bytes of picked logits with partial acceptance (30/40 guesses). STOP, RESTORE, matched resize and append matched all **62** boundaries, 51,214,848 bytes of logits and both full SAVEs. A resize to a *physical reserve* instead of a matched count left 229/236/228 slots: placement and logits then differed, even though the IDs still matched. The opt-in is `STRATA_EXPERT_LAYER_JOIN=1`; do not enable it to paper over different initial placement.

**Independent admission test, 128K coding, seed 79.** All five arms passed 118/118 with two tool calls and zero retries. In stock/cap-only/price-32/price-64 order, K3 submitted **3.458/2.776/2.837/2.111 GiB** and reached the correct answer in **26.48/22.09/24.58/26.64 s**, with **515/394/470/537** output IDs. All matched through both tool turns, then diverged on the same final question. The cap's win is not acceleration of 515 IDs. At 64 µs/MiB, loaded W1 and K3 matched all 537 IDs and the ordered selections at all 134 boundaries. K3 improved **30.78 → 26.64 s** and **25.92 → 32.62 IDs/s**, but ID-gap p90 rose **44.36 → 104.80 ms**. Saving transfer volume alone did not beat a simpler placement policy.

A second cost model used the observed W4 host-count knee, a 64-row forecast, and the estimated miss share for each physical layer from committed recency. At 64K it submitted **284 experts / 1,274,185,728 B**, waited 84.58 ms, kept 12,336 of 18,816 picks on GPU and gave **43.88 IDs/s** (same-policy W1 29.50, identical greedy IDs). The first model at 32 µs/MiB bought 286 experts and 11,995 GPU picks. On 128K coding the knee-priced W1/K3 matched all **390 IDs** and 97,026 GPU picks, but K3 **lost**: 25.44 vs 24.67 s W1, 25.64 vs 26.32 IDs/s, gap p90 120.05 vs 43.20 ms. This is a deterministic forecast of exposed cost, not a measured marginal return on each expert.

**Victim regret.** On two archived W1 routes, simulate synchronous E4/E8 on the same 128-row suffix after 128 rows of warmup. At E4, 121/170 mixed and 67/119 code arrivals were reused before the next boundary; on 6 and 14 trades respectively, the victim saw more picks than its replacement. At E8 reuse was 148/165 and 67/109; regret 12 and 17. Tightening hysteresis from `2 × victim + 2` to `3 × victim + 4` saved 64–69 copies but added **796–1,211 CPU picks**. Protecting victims used in the last eight rows changed only five selections across both tapes and cadences. These are teacher-forced, instant-publication counterfactuals. Do not convert raw picks into milliseconds or claim actual epoch per-swap profit. `victim-study/{study.py,REPORT.md}`.

**Did the actual incoming experts earn their seats?** A diagnostic worker records the selected incoming/victim pair and both committed route counters at publication. Subtract them at the next boundary or end of turn, so wrong guesses and the following prompt cannot inflate reuse. At 64K E4, W1 and K3 matched the full ordered ledger: of **567** replacements **340** incoming experts were used before the next boundary, **28** victims received more picks than their replacements, and **206** pairs saw neither expert. Arrivals/victims drew **990/106** committed picks. For E8/32: **148/173** arrivals reused, **7** regretted, **967/55** picks. A longer epoch also gives each arrival longer to earn back its copy; this is not 912 fewer CPU picks than E4.

On the independent 128K coding run, E4/64 saw **824** real replacements across 129 boundaries and 512 fed rows; **538** incoming experts saw reuse, **49** victims were regretted. Ranks 1–16 accounted for **1,413 net picks / 661 trades**; ranks 33+ for **64 / 96**. Of the 1,541 net picks, 1,210 came from pairs whose incoming expert was in a repeated core layer. This is what the traded experts did on the *actual* continuation; it is neither a counterfactual generation nor the lifetime value of the slot. Rank alone cannot price bandwidth, and pick counts are not saved milliseconds. Counts from `victim-live/{build.py,analyze.py,e4.json,e8.json,agent128.json}`, not timed runs.

Learning from which admissions earned reuse didn't beat the simple 144 MiB cap in complete cross-tape CPU replay. At the measured 64.8 µs/MiB transfer price, eight-row feedback traded 69 instead of 119 slots on code, but sent 397 more picks to the CPU (**+23.67 ms** modeled). On mixed, 92 instead of 170 trades cost 1,159 extra host picks (**+89.21 ms**). The cap didn't bind on these two 128-row suffixes. A one-epoch proxy looked better on the 128K ledger but couldn't simulate the changed future placement. No live-policy or speedup claim. `earned-admission/`.

A separate host thread submitted resident expert kernels at the start of each hybrid CPU call instead of as the CPU pool's callback. All 49 IDs, routes and the profile matched W1. In B/A/A/B order the worker delivered **42.60/17.36/41.66/40.37 IDs/s**; the second pair lost and the slow first control prevents a gain claim. The trace showed 596.03 ms outside dispatches and copies vs 525.40 ms in the original trace. Submission alone did not remove the host tail. `submit-{B1,A1,A2,B2,trace}`.

Four **output** rows share Q8 activations in the local W1 Q4 kernel; that is not sharing a weight across verifier **input** rows. Extending those four-row kernels alone to all verifier slots cut the same 1,207 Q4 dispatches from 215.4 to 147.8 ms. GU used 40 VGPR/1,536 B LDS and down 32/1,024, versus 24 VGPR and 512/1,024 B in the generic path; no scratch spills. The local four-row GU uses wave32 `v_dot4c_i32_i8`, with a fixed partial sum order. Both untraced pairs **lost**: 41.31 → 37.16 and 40.15 → 38.46 IDs/s. Do not ship that dispatch change on this evidence.

Second iteration: pair *equal weight pointers*, share Q4 loads across their two distinct input rows, keep every down result at the original index. Raw per-slot GPU output bits passed for tested multiplicities including 32 entries/16 pairs. In the ROC leg there were 4,081 pairs among 13,846 candidate picks before rejection; the grouped Q4 shader occupied **123.0 ms**. The four-row control and paired workers again matched ordered output IDs/profile/routes, but the fresh untraced pairs were **40.12 → 42.12** and **43.10 → 43.01 IDs/s**. Reducing expert dispatch time did not consistently reduce the engine's critical path. In the original four-row extension the interval outside *all recorded dispatches and copies* grew from **525.40 to 616.05 ms**; don't interpret that residual as CPU execution or card idle alone.

**Grouped verifier front.** Batching compatible Q8 Q/K/V/relative/gate projections reduced 228 → 48 launches per verifier round. At W4 the five-projection set fell **107.68 → 82.50 µs**, and 593,775 raw outputs matched stock W2–8 and W1. No spills, stock 43 VGPR and 3 KiB LDS. On live 64K K3, ABBA **42.29/43.88/42.48/43.16 IDs/s** and identical IDs, profile and SAVE; the second pair reversed. Keep it off the critical path of this change.

**Hybrid CPU leg.** On eight Ryzen cores a scratch scheduler assigned contiguous stripes of 288 down-projection rows to each CPU task, with the router's sum order unchanged. Across two W4 tapes: **1.47–1.58%** faster cold and **4.79–6.16%** on repeated inputs; 33.49 million FP32 element comparisons passed. Matched K3 ABBA on the engine gave **42.77/42.54/40.68/35.85 IDs/s**. The stock legs differed by more than either adjacent A/B effect; no CPU change shipped.

**Drafter fast path.** Grouped V reads plus truncating the last draft layer's unevaluated output rows gave same-work 64K E4 K3 ABBA decode medians **1,145.7 ms stock / 1,151.4 ms combined**. Fused RMS/Q8_1 took 1,128.1 ms in one leg, inside stock variation. FP16 draft rings took 1,126.7 ms with the same 35/38 accepted and all 49 target IDs on this suffix; the five-ring payload drops **80 → 40 MiB**, not a measured 40 MiB drop in working set at fixed physical reserve. Do not call the FP16 state byte-exact. Host vs host-LRU books averaged **75.7 / 72.5 µs** in the CPU walk over 13 actual asks, **40.75 / 40.12 IDs/s** engine throughput. The GPU-books guard trip described below yields no comparable timing.

**Cold projection skip.** The donor's request-aware cutoff transfers to hybrid prefill without changing target batch sizes. Project only the final window of a long cold text prompt (round the cutoff down to a complete target call). At **16,384 genuinely fresh rows**, 14,336 obsolete draft rows were skipped. In the closed, stable-prefill ABBA the two TTFT pairs were **20.451 → 19.121 s** and **20.401 → 19.252 s**; 49 IDs, 30/41 accepted and no repairs throughout. Diagnostic first anchor/proposal, picked target logits and full SAVE matched. The STOP/append fixture reused 4,290 rows and added only 74: a warm continuation skipped nothing. A cancelled prefill can leave the target reusable but the draft cold until it refills. Don't scale the 16K saving by the *restored* length of a 197K session. This is a TTFT port, not a faster verifier.

**Persisting draft state.** An optional scratch layout stores the absolute warm state and all five layers' committed K/V rings in **80 MiB + 8 B**; older target-only readers cannot open the extended image. With frozen placement a restarted worker restored 67,851 tokens and offered at its first eligible anchor after a **75-row** append instead of waiting another 2,048. Against uninterrupted: all nine detailed proposal fingerprints, 32 greedy IDs, 26 offers / 22 accepts, and the complete final 1.36 GB SAVE matched. First / repeated extended RESTORE took **2.31 / 1.12 s**, including **7.25 / 5.29 ms** of draft transfer; the first also scanned 16.32 GB for identity in 1.13 s. Elastic restart preserved all 1,942 surviving rows in each draft plane, but a 940 vs 942-slot target appended different bits into the ring. Persisting the drafter is not persisting target placement. See `draft/README.md` in the private run.

On a separate 64K restart pair at frozen placement, both fresh workers had the same 67,844 target rows before the first 114-row tool request. Target-only COLD did not reach 2,048 new committed rows across all three turns; WARM offered at position 67,958. All **418 output IDs**, two tools and 118 checks matched. Including RESTORE the correct answer took **29.53 → 20.67 s**, COLD → WARM (excluding it, **28.32 → 18.36 s**). Decode **17.05 → 28.45 IDs/s**, native p90 **64.8 → 120.9 ms**. It did not persist the sampler or the expert ranker.

On 48 recorded anchors, the CPU replay at 114 rebuilt rows matched 101/144 target tokens as a consecutive prefix vs 102/144 warm, but just 39/48 complete draft triples matched warm. `partial/qualified-197k-coding`, `partial-oracle/`.

## Full-history compact KV

[LexiEngine's layout](https://github.com/W61k3r/LexiSuite-Releases/wiki/LexiEngine-Inkling-2) rotates Q/K with WHT128 and V by two WHT64s before q4_0 packing. Its [RX 7900 XTX results](https://github.com/W61k3r/LexiSuite-Releases/wiki/Benchmarks) use a different engine and GPU; they do not isolate the effect of rotation. We compared codecs without dropping global rows: eight global **logical visits** and an unchanged recent Q8 tail. The 40 exact local SWA rings are not counted as full history.

- **Accuracy, fixed inputs.** Six recorded predictors on three real 64K/197K code/reason traces, all eight visits and 24 query heads: 1,152 head observations per arm, not independent tasks. The native CPU replay reproduced captured Q8 GPU output to max gated relative L2 `3.62e-6`. With Q8 K, p95 relative L2 was **6.40%** for stock refit V4, **5.51%** raw q4_0 V and **4.57%** WHT64 q4_0 V. With K and V both compressed: raw/raw **17.12%**, rotated/rotated **13.63%**, the latter with max **54.93%**. K4 changes softmax: rotated K kept the same top attention row on 86.55% of these head observations. These are **attention** ranks, not predicted vocabulary tokens. No static head mask follows from six queries.
- **Bytes.** At 200,000 rows and 197,888 sealed cold positions, global payload Q8/Q8 = **3,320.31 MiB**, K8/V4 = **2,547.31**, K4/V4 = **1,774.31**. These include scales; they are not measured savings of physical VRAM or a promise of 1,546 MiB of available slots. Rotating a cold numerator also requires returning to the native basis before mixing hot rows and applying the gate.
- **RDNA2 kernel.** Synthetic full-history causal attention; same signed-nibble refit for the packed arms, **without WHT**. Receipts: `kv-leaf/share/{build,guard-s15,results.md}`.
- **Where to spend precision.** With half the 64 `(global visit, KV head)` groups at K8, remaining cold K and V rotated at four bits, the 200K projection is **2,265,776,128 B**. **Can the saved space actually fund experts?** Yes, in a private native worker using Q8 K / stock symmetric V4 and E4 K3 with full history and exact compact SWA. **Group mixed reads and remove legacy import.** Reuse the four-wave kernel while keeping each query's W1 chunk boundaries. On the 199,069-row untraced wire fixture, dense / serial V4 / grouped V4 K3 reached **28.74/27.31/32.81 IDs/s**. At 67,840: **42.60/30.94/35.99**. The grouped reader matched serial V4 in 42 million FP32 logit values and 207 placement probes, including a seal transition. To price the real request rather than codec import, prepare native layout 3 offline, then restart on the 194,973-row snapshot and append 2,048 rows plus the question. At 197K reasoning/79, dense / grouped-V4 RESTORE **3.12/2.50 s**, first-ID latency *after* RESTORE **10.09/25.48 s**. Even crediting V4 its whole RESTORE saving, recovering the first-token deficit at the wire decode rate would require ~3,350 more IDs, with only 2,848 context positions left before tool returns. This is a codec **and placement** outcome. Keep dense global Q8. `dense-v4/grouped/`.

**Does a smaller attention error preserve real answers?** A separate W1 test round-tripped **only cold global V** in a 65,796-row SAVE through WHT64/q4_0 and back to Q8. All K, the newest 2,052 global V rows, local rings, recurrent state and history were untouched. Both arms restored the native format and used equal space: this tests quality, not speed or the native V4 codec. On 64K coding/reasoning × seeds 42/79, Q8 passed **4/4**, round-trip V passed **3/4**. All 16 required tool reads succeeded with zero retries. On coding-42 the treatment saved 50 reasoning IDs (26.09 → 23.85 s); on reasoning-79 the first two turns matched, the final turn diverged at **output 4**, reasoning IDs increased **366 → 519**, and the answer hit its 512-output turn limit. Lower attention p95 alone is not a quality gate. See `kv/quality-64k/paired-ab/`.

**Reasoning efficiency is a separate axis.** On the [earlier 197K W1 screen](../../../docs/goals/2026-11-25-adaptive-global-kv/production.md), dense/K256/full-history V4/K256+V4 scored 4/4, 2/4, 1/4, 4/4 at 4,900 MiB. At 5,412 MiB both dense and the combination scored 2/4, exchanging a success. The hard 8K window scored 0/6 vs dense 6/6 on long tasks. Removing the K256 guard would verify dense scores instead of the sparse W1 policy: a fixed-placement retrace changed 11/25 draft tuples despite 33 matching greedy IDs. [LoopCD-Hidden](../../../docs/goals/native-donor-recon/contrast.md) shortened the last reasoning turn on two cold, fully graded billing runs, saving **1.03/2.72 s**. Hidden also changed saved coda visits 42–47 before the first picked ID changed. Reuse as an unguided prefix or verification with the wrong guidance mask is not exact. These results do not justify mixing either mode with dense DFlash2 or claiming a general reasoning improvement.

**Can we retain native Q8 bits instead?** A CPU screen on the 65,796- and 194,973-row dense snapshots reconstructed the sampled original scale bits and signed codes across all eight global visits, eight KV heads and history ages. After exception masks, page indexes, alignment and native fallback, signed 4/5/6-bit packing and simple residuals freed **zero whole expert slots**; retaining only exceptional high bits saved just 0.57 MiB on long K, nothing on V. Packing just scales in indexed 128-row pages projected **26.12 + 22.46 MiB** at 194,973 rows. That is below a 64 MiB arena growth unit. Zstd-3 on independent pages projected 192.59 MiB, but doesn't provide the 16-code random reads used by the leaf. These are storage estimates, not measured transfer or decode improvements. `kv-lossless/REPORT.md`.
