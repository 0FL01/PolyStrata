# DFlash2 × existing Inkling long-context options

These are research probes, not a rollout or a change to the target's supported modes. RX 6700 XT (gfx1031), Ryzen 7 5700X, Tideglass-Inkling-2-Mini-Unbound-v2.1, native DFlash2 Q4_0. Every device process takes the same RECON `gpu.lock` and uses `run_guarded.py --warn-amdgpu-faults`, with the 1536 MiB floor unchanged. Results and captures are private under `R/interactions/`, where `R=~/.cache/opencode-tmp/opencode/polystrata-runs/dflash2-recon`.

## Exact SWA: direct guarded pair with DFlash2 loaded

One fresh **16,384-ID** prefill per leg using the first 16,384 actual IDs of the archived 197,021-ID Agent history. No restored target/drafter state, no follow, no lookup, greedy seed 42, 33 emitted IDs, 2048 prompt batch, native dense global Q8. Identical private live-probe ELF both legs. Target reserves room for width 8; DFlash2 offers up to 3 IDs and runs the existing nonserial verifier. A 4096 MiB research expert-only limit, `--kv-whole` at 16,545 maximum rows, 2048 MiB reserve, 8 workers, frozen split, zero swaps, zero adaptive prompt CPU share, no early prefetch and funding off isolated just the SWA switch. Both arms held the same **956** resident expert identities and relative offsets within each layer, at prompt start and exit (`60d3aef0a110a847`). Engine and library fingerprints and the exact prompt/profile hashes are in `live-16k-fixed-audit/plan.json`.

- **33/33 greedy IDs and all 14 accepted-prefix decisions matched**, with 18/39 proposals accepted, including five first-proposal rejects and partial prefixes. Every committed row count matched. This compares the *same live verifier* across layouts, not wide verification against serial W1. Matching accept decisions do not establish that unaccepted proposal tuples were identical.
- **Byte parity** in all 33 selected FP32 full-vocabulary target vectors (**26,407,656 B**), canonical convolution/SWA checkpoint (**92,875,776 B**) and committed global KV rows (**285,769,728 B**, through 16,416 rows). These are private diagnostic tapes and do not assert equality with a separately run W1 target.
- The stock ring had 3,071 rows per local visit. Compact used **1,031**, with a 3,086-row aligned scratch view borrowed from `input_[0]`, not a new allocation. **320 actual staged prompt visits** and **14 direct-ring verifier windows**. No staged verifier windows, no deliberately targeted verifier wrap boundary in this fixture. This exercised real wide staged prefill and then both accepted and rejected windows.
- Ring payload fell **177,561,600 B (169.34 MiB)**. Sampled minimum *whole-card* free VRAM rose **2391.25 → 2550.60 MiB**; not an isolated per-process memory reading. No guard stop or fresh warning, only a preexisting boot fault warning. This is a correctness/memory test, not a speed qualification: one diagnostic A/B with no A/A or reversed-order repeat, shared host, checkpoint/logit dumps enabled.

The production [Exact SWA contract](../../../docs/goals/2026-11-25-exact-swa-memory-compaction.md) explains the rollback geometry: retain `1023 + configured verifier width` rows, not just the W1 tail, before a window writes any guess. Oldest-first state is independent of the physical ring, and the borrowed prefill stage preserves modulo-16 Flash phase. The DFlash2 tap ring is separate; the live wrapper appends only the prefix retained by `keep()`, not the whole offered window. Prior SWA qualification included forced wrap, canceled/replayed prefixes and rejected-row overwrites; that is **DSpark** evidence, not a claim that this DFlash2 fixture reran every lifecycle case. Real production used compact SWA plus slot funding; freeing space and spending it on a changed placement are separate experiments.

Two preflight attempts are retained. A full frozen combined startup budget could not grow into 16K. Switching to `--kv-whole` while retaining the production combined-cap flag was also rejected; that cap requires growing VMM. Neither ever completed a prompt. The valid pair fixes the expert arena alone in the overlay, rather than lowering the guard/reserve or changing the limit only for one arm.

## Global KV and LoopCD boundaries

| Mode | Actual compatibility boundary |
|---|---|
| K256/P128 | `Inkling2::attention` dispatches selection only for `serial_decode_ && n == 1 && !windowed_` and a worthwhile span (first **35,072** causal rows). A wide live verifier would skip K256 even with an index and would score a different target. Prompt/append kernels do not use K256 selection. W1 positional state can be captured natively, but Q8 file identity says nothing about the attention policy used to produce those states. |
| V4 | Keeps absolute native Q8 K and uses rolling Q8 V plus lossy old V4 blocks; requires growing VMM, Q8_0 and no DSpark or `--kv-whole`/pool. Seal runs before a call and on canonical capture at the committed position. A wide call crossing a seal boundary keeps the old page in Q8 for later rows where W1 would already read V4; even without corruption this is not same-policy W1 verification. Prompt prefill can already see sealed V, unlike K256-only. Ordinary `Engine::keep()` restores a recurrent snapshot and advances position; it does not transact codec metadata/bytes or certify rejected-row rollback of the wrapped V pool. No corruption was induced or claimed here. The proof needed before removing the block includes a partially rejected window across seal/wrap, replacement of rejected rows, and checkpoint/SAVE/RESTORE parity against V4 W1 on that same history. V4 backing/checkpoint bytes intentionally differ from native; compact files cannot be opened as dense. |
| LoopCD-Hidden | No production engine switch and no DFlash2 qualification. The prior isolated Native Donor RECON blends state before coda; even when the first emitted ID matched it changed the saved coda KV and convolution state, visits 42–47. A guided terminal row can later become canonical interior context. Before any live window or warm hit, replay from a canonical checkpoint that precedes the first guided row using an explicit guidance mask. Keep/rerun needs the original mask. No direct DFlash2 test here. |
| Skip-Coda Logits | Same Native Donor experiment, distinct policy: combines weak and strong readouts with APC to change the final scores; pre-coda taps alone cannot tell whether a proposal remains correct. Previous matched-history SAVE had no direct state difference (next committed token can still differ); previous guided DSpark samples are not DFlash2 evidence or a warm rollback proof. No direct DFlash2 test here. |

The [live overlay](../live/build.py) explicitly rejects both K256 and V4 (even when its serial verification flag is selected) and does not support server RESTORE. Do not relax the codec check for a batched live experiment. The serial retrace uses a separate W1-only target, then loads DFlash2 in a **different** process for replay. The production [qualification](../../../docs/goals/2026-11-25-adaptive-global-kv/production.md) is the source for single-mechanism and hybrid lifecycle/quality results: e.g. K256 alone was rejected as a near-cap automatic default on a held-out reasoning trajectory; V4 reduced storage but the original bounded wide reader regressed real prefill, and H2 is its own approximate opt-in (off here). Faster W1 or same greedy IDs on one fixture are not parity or solved-task evidence. See the earlier [LoopCD measurements](../../../docs/goals/native-donor-recon/contrast.md) and [acceptance gates](../../../docs/goals/native-donor-recon/qualification.md#loopcd-is-a-change-to-the-target). Do not combine guidance, codecs or adaptive placement in the next direct test.

## Serial codec retrace: measured at 131K

One 129,015-row native snapshot and an identical 2,048-ID prompt append reach anchor **131,063**. Compare dense, K256-only and V4-only, keeping compact SWA on in all three, with no H2 and no slot funding. The unchanged target W1 sampler picks each arm's own greedy continuation; no saved IDs are forced. DFT1 records carry the absolute input position, token and prompt/generated flag plus four actual target FP32 taps, checked against the executed history. A proposal counts only up to the **first** wrong position against that policy's future. Fixed-position and closed-loop replay use at most seven guesses, requiring eight captured committed rows, so the last positions and final emitted-but-unfed ID do not enter the acceptance score. Compare proposal tuples only at common-history anchors, and do not attribute differences after the first target-ID divergence solely to the codec. Checkpoint bytes are separable from committed-ID identity; a differing checkpoint on differing histories is not same-history state evidence.

All three legs emitted 33 IDs and held the same **598** resident experts and within-layer slot offsets from the first append call to exit (`066ee2de89f7ad0e`). The arena was fixed at 2560 MiB, with the same 2048 MiB reserve, 8 workers, no swaps and no adaptive CPU share. Replay used the same native Q4_0 draft executable and weights across tapes. All six guards completed with no stop or fresh warning; minimum sampled free VRAM across target arms was **3087.17 MiB**. The replay timings are not target or combined wall times.

| Target | Policy dispatches | Greedy prefix vs dense | 25-position K7 prefixes, accepted/offered | Same anchors, first 3 guesses only | K7 closed-loop replay |
|---|---:|---|---:|---:|---:|
| Dense Q8 | 0 sparse / 0 mixed | reference | 45/175 | 37/75 | 20/70 (10 rounds) |
| K256 only | 256 sparse / 0 mixed | 33/33 IDs | 42/175 | 35/75 | 19/77 (11 rounds) |
| V4 only | 0 sparse / 280 mixed | first mismatch at index 13 (62 → 196977) | 31/175 | 27/75 | 14/84 (12 rounds) |

- **K256:** all 2,048 prompt records matched dense bit-for-bit. Taps 23/41/48 first differed on the first W1 input at absolute **131,063** and differed on all 32 fed generation rows; tap 5 was exact on the whole history. Consequently **11/25** full proposal tuples differed even though all 33 greedy IDs and the committed-ID digest matched. Same-history canonical bytes did *not* match: the byte scan found changes in convolution visits 5–47 and all 35 SWA visits after visit 5. K256 selects historical rows only during serial generation; the first sparse visit is visit 5, after the entering tap at that visit.
- **V4:** taps 23/41/48 first differed at **129,015**, the first fresh prompt input, and differed at every compared shared-input row; tap 5 remained exact. **8/13** proposal tuples differed on common-history anchors. The final committed IDs differ, and the V4 checkpoint includes a separate Q8 V tail (111,806,976 vs 92,875,776 B); do not interpret its different hash as isolated same-history state drift. This compares a native-to-V4 import plus V4 continuation, not a V4 history generated from empty.

These are one direct suffix fixture, not a ranking of the policies or a speedup estimate. In particular, identical greedy IDs under K256 did not imply equivalent features, proposal prefixes or target state even before any token-history difference. V4's loss of prefix acceptance on this fixture does not isolate changes in the draft from changes in what the target prefers after the branch diverges. Neither result permits removing the live-window rejection.

Receipts: `serial-129k-policy/{plan.json,result.json,same-id-state-difference.json}` and each arm's guarded target/replay logs and private tapes. SWA receipts: `live-16k-fixed-audit/{plan.json,compare.json,stock/result.json,compact/result.json}`.

The two earlier serial preflights (`serial-129k-direct` and `serial-129k-fixed`) stopped before `GEN`: the wrapper originally expected `READY` before the informational startup line and `RESTORED` before the `SWAIT` progress lines. Their logs are retained, but they do not count as target trajectories or codec legs.

## Reproduction

Use completed Release HIP gfx1031 Ninja objects; both builds write only their new destination. The W1 overlay reads the existing RECON `probe-bin` source instrumentation for DFT1, not its binary; only the privately compiled three objects change. Its main uses native server generation with no drafter, no follow, no lookup and width 1. It records policy dispatch count and canonical checkpoint bytes. The offline replay starts with all 2,048 preceding target features at the anchor, not stale baseline features or a missing/restored drafter history. The archived Agent prefix is extended with a separate archived long-code token span, not the parent's shared long-tap suffix. This is a controlled splice of authentic tokens, not an agent/task-quality run.

```sh
R="$HOME/.cache/opencode-tmp/opencode/polystrata-runs/dflash2-recon"
I="$R/interactions"
python -B rdna2-rnd/dflash2/interactions/build.py "$I/live-bin"
python -B rdna2-rnd/dflash2/interactions/swa.py "$I/live-16k-fixed-audit" --audit
python -B rdna2-rnd/dflash2/interactions/build.py "$I/w1-bin" --serial-probe-source "$R/probe-bin"
python -B rdna2-rnd/dflash2/interactions/retrace.py "$I/serial-129k-policy"
```

Use fresh names for repeated builds or runs (`--binary` selects a fresh build). Source sessions are opened read-only; profiles and outputs are independent. Keep raw tapes, IDs, source sessions and model weights local.
