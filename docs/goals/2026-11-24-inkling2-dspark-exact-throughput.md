# Goal: faster exact Inkling DSpark decode on RDNA2

Status: active
Source: user request to raise DSpark decode t/s without divergence, then implement, reprofile, commit, push, and deploy wins.
Last updated: 2026-11-24

## Objective

Raise end-to-end decode throughput for Inkling-2-Mini Q4_0 with native DSpark on the RX 6700 XT without changing the target answer. Keep the default serial deployment until speculation matches it with live swaps and clears the prior rollout gate.

## Required outcomes

- R1: Keep only reproducible decode wins with exact relevant boundaries and greedy token IDs on gfx1031. Evidence: untraced paired engine runs, token IDs, and the closest kernel/state check; report losses and limitations. Status: in progress.
- R2: Push each qualified change to `origin/main`, build Release, deploy that binary without unqualified configuration changes, and use it as the next baseline. Evidence: `6f233b3e` pushed and deployed, gfx1031 Release SHA-256 `cf930340aafe86c6ffd3aa7abc99b9a1c853192ff77699a2a34cd2964bc5a6c6`; `/health` loaded at 200K and a chat emitted 64 tokens. Status: verified for value reuse.
- R3: Qualify live speculative verification against serial, then measure adaptive decode against plain. Evidence: greedy IDs, fixed-seed sampler, committed state, and tool/code/JSON and 16K speed gate from the prior [DSpark goal](2026-11-24-inkling2-dspark-disk.md). Status: pending.

## Scope and checkpoint

`src/poly/inkling_dspark.cu`, the native Inkling verifier and its expert kernels, and affected documentation; use isolated prototypes outside the source tree. Keep model, precision, reduction order, routing/sampling, disk format, VRAM reserve and default no-drafter path unchanged unless separately proven exact. Serial GPU runs with the existing guard; no gfx1031 performance counters (`rocprofv3 --pmc`).

Complete the smallest unresolved outcome; let measured results choose the next experiment rather than following a fixed route. Stop a line of work that cannot meet exactness or end-to-end speed in its envelope; don't treat a leaf win as a rollout result.

- Initial baseline: `e116808d`. Live budget 3 vs attached budget 0 diverges at output 35 (2K) and 59 (16K); at 64K it is 31.34 vs 32.48 t/s on one restored fixture. In the probe, the first drafter attention variant preserved all FP32 intermediate/output bytes and reduced the 64K engine dispatch from 11.84 to 7.27 ms. The separate Q4_0 verifier tile leaf was exact; front-wait removal and commit fusion did not improve decode.
- Checkpoint 1 (R1): integrated gfx1031 value reuse behind `STRATA_INKLING_DSPARK_REUSE_V=1`. On the RX 6700 XT, fixed schedule and fixed 909 experts, restored 16K, four untraced pairs over 192 greedy IDs: median 30.014 → 30.754 t/s (+2.47%, four of four pairs). All IDs, proposed IDs and probability bits, verification decisions and the recaptured committed file matched; reported median first-proposal time was 7.49 → 6.13 ms. The earlier 64K live matched-route test measured 33.000 → 34.657 t/s (+5.02%) and exact IDs, decisions and snapshot with the same device instructions. Other live runs varied even in A/A; do not infer adaptive parity from these numbers. An isolated frozen 64K confirmation was stopped at 1,433 MiB free by the guard, with no GPU fault; use reduced arena and no direct staging in the next 64K control.
- Checkpoint 2 (R1/R3): with the value-reuse build, fixed 64K ROCm trace measured 12.271 → 7.432 ms for full drafter attention and 17.049 → 12.266 ms for the warm first proposal; traced width-4 target verification is still about 106 ms (frozen placement; not production latency). Splitting the workgroups across fewer queries was slower; score-loop unroll changes overlapped baseline variation. A width-two cache journal plus serial fallback matched all 192 greedy IDs, all FP32 logits sampled from, and the committed file at live 2K and 16K (two legs each); forced decode slowed 38.145 → 32.184 and 33.841 → 27.326 t/s respectively. At 2K/16K, 42/58 of 106 windows replayed the second row for a placement mismatch. Production verifier is unchanged.
- Checkpoint 3 (R3): widening the resident Q4_0 tile cut traced width-four gate/up and down sums from 9.76 / 5.35 to 6.66 / 3.38 ms, but target wall time was 72.81 → 71.94 ms and untraced decode medians fell 3.02% / 3.98% at 2K / 16K. The 2K live journal found the first placement mismatch in visits 0–15 in 33 of 42 replays. Scaling measured replay cost by the fraction of visits skipped projects 35.94 t/s for partial replay vs 40.61 t/s serial (a model, not a measurement of a partial implementation); deleting all replay cost in that run would project only 42.10 t/s. Do not widen or ship either verifier path.
- Checkpoint 4 (R1/R2): keep the cache-only tile specialization under the same `STRATA_INKLING_DSPARK_REUSE_V=1` flag. A separate 64K engine trace measured 7.274 → 3.331 ms in full-context attention on top of V reuse; the short-ring launch was 0.136 → 0.079 ms. From restored prefixes with fixed placement and windows, four untraced pairs of 192 greedy IDs: 64K 27.377 → 28.416 t/s (+3.80%, all four pairs), 16K 30.886 → 31.254 (+1.19%, pairs disagree), 2K 33.870 → 33.970 (+0.30%, pairs disagree). Every token, proposal ID/confidence bit and round decision matched, plus the checked final snapshots at each length and the seeded 16K pair. The leaf also matched partials and outputs at 28 positions up to 200K, with and without the 1,024-slot ring. These are same-verifier results, not adaptive rollout.
- Next (R1): test drafter Q8_0 down without packing (174.6 → 105.8 µs cold on real weights) against the new baseline, and check whether skipping unused queries/output in the last drafter layer pays when all eight K/V rows are still present. Keep changes only if they improve exact end-to-end decode, not merely a dispatch.
