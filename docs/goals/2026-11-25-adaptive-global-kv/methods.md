# Global KV literature, read against Inkling 2 Mini

Sources below are primary author papers/proceedings. No reported CUDA/A100 throughput or benchmark quality transfers to RDNA2.

| Paper (sections checked) | What it actually does | Relevance and limitation here |
|---|---|---|
| [DuoAttention](https://arxiv.org/abs/2410.10819), §§2.1–3.3 | Learn gates against synthetic passkey retrieval, with weights frozen, then statically classify **KV heads** (whole KV group in GQA). Retrieval heads store dense history; streaming heads retain initial and recent **tokens** and discard the middle, reducing permanent capacity and reads. | Inkling already has 40 architecture-defined sliding visits. Its eight global visits are not thereby shown to have any disposable KV groups. 3 query heads share a KV head per visit; one long-range query can require that group's bytes. Its virtual projected sink has no K/V row, unlike Duo's initial sink tokens. Per-visit calibration and independent retrieval/quality needed for a lossy arm; fails an exact requirement by construction. |
| [QUEST](https://proceedings.mlr.press/v235/tang24l.html), §§3.4–3.5, Algorithm 1 | Maintain per-key-channel page extrema; sum `max(q_i min_i,q_i max_i)` as a score upper bound. Fixed top-K of those page bounds goes to attention, with no omitted-mass proof. Paper retains exact KV for future queries, skips first two Llama layers in its eval, and uses page size 16 in the principal experiments. | Useful no-RoPE metadata sketch. Bound applies to **actual** Q8-dequantized K with conservative FP arithmetic and last-1,024 bias treatment. Does not create capacity savings without separate placement or permanent loss; all three queries in a GQA group need their own guarantee. Report realized miss union, metadata reads, and fallback, not a top-K hit rate alone. |
| [SparQ Attention](https://proceedings.mlr.press/v235/ribar24a.html), §4, Algorithm 1, Appendix B | Largest-magnitude query components select a K feature slice scanned across history; approximate ranks pick rows, then fetch full K and V. Original single-head variant mixes in a running mean V with estimated missing probability. GQA sums query magnitudes to choose features and sums approximate scores within a group to choose rows; authors omit that mean correction for their Llama 3/Mistral GQA tests. Efficient layouts can duplicate K in channel-major order. | Read sparsity, not capacity reduction. Existing Inkling Q8 is row/32-channel scale block, not a cheap channel scan; second K layout and gather have cost. Mean V/partial scores are not exact or a certified tail. Do not rank different query heads by one uncalibrated summed score and claim all 3 retain mass. |
| [KIVI](https://proceedings.mlr.press/v235/liu24bz.html), §§3.2–3.4 | Asymmetric 2-bit grouped quantization: K per channel across token groups, V per token across channels; recent residual full precision, fused dequant/matmul. Changes stored capacity and bytes read; attends all history rather than query-aware page selection. | Requantizing already committed Q8 codes/scales to 2 bits is lossy, not exact representation. Requires gfx1031 kernels/memory layout and quality calibration if approximation allowed; do not apply their FP16-relative result to an existing Q8 cache. |
| [Twilight](https://papers.nips.cc/paper_files/paper/2025/file/ad2f57116d62a9d8dcfaba6a168715e4-Paper-Conference.pdf), §§3–4 | Oracle top-p uses true normalized mass and gives an output error bound; deployed pipeline starts from a selector subset and refines it with 4-bit key scores and top-p. | Oracle tail-mass criterion is useful, approximate candidate softmax is not a certificate over omitted pages. Retains base KV; additional K metadata is not free. |
| [BLASST](https://arxiv.org/abs/2512.12087), Algorithm 1, §3, Appendix C | Read K and compute block scores; use online softmax block max vs running max and a calibrated threshold to skip exponentials/value loading/PV. | Different axis: does not save K reads, not a lossless shortcut for signed/FP32 reductions, no capacity gain without offload. Current Inkling decode issues V before scores; a K-first split requires a new measured kernel, K alone is ~1.62 GiB at 200K. |
| [InfiniGen](https://www.usenix.org/conference/osdi24/presentation/lee) ([paper](https://www.usenix.net/system/files/osdi24-lee.pdf)), §§3–4 | Keep partial skewed key cache on GPU and rehearse future query using the preceding block input and partial projection; prefetch predicted important CPU KV. | Actually addresses offload and overlap, but approximate. Inkling visit Q depends on current hidden and depth/message/conv state. A predictor may prefetch only; an exact fallback must get all required bytes. No eight-visit lookahead in the DMA timing. |
| [ShadowKV](https://proceedings.mlr.press/v267/sun25b.html), §§3–4 | Approximate low-rank **pre-RoPE** K and reconstruct selected keys; post-RoPE landmarks/outlier chunks choose sparse values fetched from CPU. | Real capacity + read trade, but Inkling has no pre/post-RoPE distinction; low rank after its learned projection, dynamic short conv and clipping must be checked and would not preserve existing Q8 bits. |
| [FlashAttention](https://arxiv.org/abs/2205.14135), Algorithm 1 | Tiled exact in real arithmetic, communicating softmax normalizer and weighted values without materializing the score matrix. | An exact dense streaming fallback is mathematically possible, but cannot skip arbitrary keys and may change summation order. Stock already fuses four physical planes and reuses each K/V read across 3 queries; a new physical storage policy needs fixed chunk/lane order and parity. |

## A bounded tail is not exact inference

For a fixed query head, let `s_i` be the stock logit and `s_sink` its projected zero-value sink logit. Keep current/recent rows and evaluate selected old rows exactly. Set `A=exp(s_sink)+sum_eval exp(s_i)` and `E=sum_unread n_page exp(U_page)`, where `U_page` is a conservative upper bound on every valid unread logit for that head. Use a shared exponent offset or log-domain arithmetic, and upper/lower rounded bounds for `E/A`. The omitted probability is at most `E/(A+E)`. If every unread value coordinate has `|v|<=M`, then pre-gate `|y_full-y_eval| <= (M+|y_eval|) E/(A+E)` per coordinate; the elementwise sigmoid gate is at most one. Per-page value intervals could tighten and diagnose this. This is a deterministic **operator error bound** in real arithmetic with finite values, not an output, state, router or greedy ID identity certificate. A certificate for top score/rank alone says nothing about the sum of many small terms. The guaranteed `n_page` is valid causal rows, not padded rows; a page crossing the last-1,024 boundary must include the learned relative term or stay fully on the exact recent path.

For a proof about the *existing* numerical operator, extrema over real K are insufficient on their own: its `decode_q8_kernel` accumulates `q*int8` within lanes, applies half scale and `1/sqrt(128)`, then adds the learned relative term and reduces wave32 shuffles in a fixed order. Metadata rounding and floating rounding need conservative margins in the relevant direction (FP16 min rounds down, max up; inward quantization is invalid). Q is already clipped and scaled logarithmically above 8,192, and K uses post-convolution Q8 bytes; no RoPE to invert or shift. `expf` underflow after a global max does **not** prove deleting a page is bit-neutral: each chunk runs local lane maxima and online FP32 updates, and final chunks merge in order with the sink once. Keep chunk geometry based on original span and configured `STRATA_INKLING_DECODE_CHUNKS` (160 in the snapshot), not selected count. If strict bits are required, read/decode every contributing row or prove the exact sequence of arithmetic states unchanged, including zero signs/underflow and both Q8 scale/code payloads. Validate original chunk partials, FP32 output, packed Q8_1, committed sequence state, save/restore and held-out greedy IDs. A few matching IDs are not proof; an attention-only epsilon can grow through repeated visits/routing/state.

At 200K, FP16 min+max for 8×128 K channels costs 4,096 B per **visit page**, before indexes/V norms. Metadata for all eight visits costs ~390.6/97.7/48.8/24.4 MiB at 16/64/128/256 rows respectively (last-page alignment can affect this slightly); FP32 doubles it. A full metadata read per generated query/visit costs that traffic even if almost no K/V data is read, unless a tighter hierarchical index changes the work. Broader pages reduce overhead but inflate the page-level maximum and the number of unneeded row bytes fetched. All four payload planes packed into a whole-visit page, as in the leaf, only need one H2D for the selected page, but the page is selected if any of 24 queries needs it. Per-KV-head layout reduces that union to 3 queries and 272 B/row/head, with smaller DMA granules; not tested here. No blanket equivalence to a single-query top-K budget.
