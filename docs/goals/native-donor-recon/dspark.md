# DSpark: projection cost, proposal quality, and verification are three different tests

**Keep production W1/no drafter.** The zero-copy indexed head works on this GPU. It does not fix the target verifier. Unlike the Tideglass profiles elsewhere in this study, these dedicated draft/K controls used the local unsloth **Inkling-2-Mini-Q4_0.gguf** target and the matching `dspark-Inkling-2-Mini-Q8_0-F16-head.gguf`.

1. **Draft attention and capacity.** Donor #207's FP16 paged, contiguous split-K attention, coalesced half2 dots and batch/TP graph sizing differ from native `src/poly/inkling_dspark.cu`: two short layers, one global, Q8 planes with FP16 scales, FP32 local block rows, 32-key tiles, strided split assignment and an ordered FP32 merge. The eight draft rows are bidirectional; a cap of three guesses does not permit dropping five K/V input rows from the early layers. Prior *local* exact V reuse and cache-only tiling already cut the 64K draft dispatch **12.27→7.43→3.33 ms**; their fixed-schedule combined 64K engine win (+7.22% in the earlier campaign) does not establish today's adaptive verifier. Donor graph cap reclaimed 2.70 GiB from many-request target PIECEWISE captures. We don't allocate that graph pool. Don't port BF16 tap storage or FP16 accumulation as a memory optimization promised to be exact.
2. **Zero-copy head.** Native Q6_K base rows are 1,890 B each; 200,058 logical, 201,024 physical. Index the existing weight pointer by a sorted global ID, retain the stock Q8_1/dot reduction, write compact rows, return global IDs. RX 6700 XT: 24 rotating event samples, three normalized real embedding rows as activation surrogates, real GGUF head, 32,768 IDs, compare full → indexed → prepacked compact. Three-row warm projection **1.111→0.205→0.202 ms**; after touching a disjoint 96 MiB allocation **1.704→0.554→0.549 ms**. Every selected FP32 result matched (262,144 checks per 32K list across one/three rows and indexed/copied arms). Excludes quantization, W2, argmax, host work, and verification. Indexing avoids *adding* 59.06 MiB of copied base weights; there is no such duplicate in production. Actually narrowing rank-major `ds_w2_` and draft-only base/bias could release about **81.69 + 5.10 MiB**. Not the donor's 342 MiB; not freed by the timing harness. Measure loaded VRAM/headroom before funding new experts, whose placement can change the target.
3. **Restricted vocabulary with real proposals.** Scored 2.57M code and 0.51M doc tokens and kept structural IDs; only 18,931 positive/special IDs. Lowest-unused vs independently localized fill of the remaining 32K positions. No eval outputs used in counts; localization was motivated by the first screen, not a blind quality test. Scratch masked *full* scores to `−inf` before the existing argmax/confidence; this measures real recurrent proposals, **not** speed. For the same serial target trajectory, JSON stock→either 32K first-proposal acceptance **65/78→59/78**, third-prefix **38/76→31/76**, seventh **12/72→6/72**. Russian stock→first list→localized: first **47/78→41/78→46/78**; changed chains 46→9 between lists. Real IDs and 4-decimal logged confidences matched in scratch unmasked A/A. Even along unchanged proposal prefixes, confidence changed by up to **+0.2451** on JSON. Coverage is an upper bound, not acceptance; subset-normalized probability is a different controller input. Keep global lowest-ID tie semantics, never restrict the target sampler.
4. **Dynamic K and target cost.** 48-token JSON prompt, 80 generated IDs, fixed 203 GPU slots/950 MiB diagnostic budget, 8 workers, same seed and greedy settings. K3/K7 serial observers matched **all 80 target IDs and 231 shared proposal IDs** (and 231 logged confidences at four decimals). K7 observed contiguous successes by depth: **65/78, 49/77, 38/76, 31/75, 24/74, 18/73, 12/72**. Median warm cost per proposal **3.97, .44, .42, 1.64, .44, .42, .42 ms**: native already groups first three vs later base-head work. No benefit from importing the donor's duplicate short B1 graph without a corresponding native expense. In actual adaptive execution with the same frozen target, attached W1 **16.38 ID/s**, K≤2 **12.71** (36/43 reported accepted), K≤7 **14.33** (25/29). Both first differed at output **60 (1-based), 174948→149899**. This is a geometry/verification qualification failure, not proof that the shortlist changed the *serial* target, nor an estimate for the much larger production cache.
5. **What to build instead of importing a verifier.** Avoid modifying the commit boundary until the mechanism saves more than it costs. The target's native quantized output head can reuse the *indexed projection primitive* for other provably sparse work (e.g. [APC weak readout](contrast.md)); that opportunity has no speculative replay or active-vocab calibration dependency. If exact speculation is revisited, preserve W1 per-row reductions and simulate/commit per-row slot transitions and accepted taps before deciding whether to batch any work. Instrument first divergence in FP32 logits/route, not merely first changed token. A prior exact two-row journal paid for replays and lost to W1; an older optimistic one-pass oracle still missed the rollout screen. Only after such a verifier exists should we charge a dynamic K rule against measured local widths, allow K=0, and compare held-out success by deadline. A separate suffix-copy replay of 14 turns/1,553 feedable rows had only **4.6–4.9%** hindsight gain at the archived prices; it was not a measurement of DSpark acceptance.
