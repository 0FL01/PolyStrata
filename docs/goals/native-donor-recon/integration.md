# Production integration plan — RX 6700 XT, Inkling 2 Mini

**Keep the current binary and its defaults.** None of the exact donor scheduling/ISA changes tested here has demonstrated a repeatable improvement in time through a successful task. The strongest *quality* lead is pre-coda Hidden: equal grade and shorter completions on a real tool task, but two seeds on one cold-rebuild task are not a release qualification. Keep these tracks independent so a correctness failure or a timing win is attributable.

**Close the two leaf-only wins rather than queueing them by default.** For #196 scalar fetch (direct Q8 H2) and #195/#206 same-order DPP reductions (Q4 slots), [actual native ELF A/B](kernels.md) exercised both shaders and had matching token IDs. Neither effect survived paired engine timing. Don't add an environment variable, rewrite LDS or repack weights for them. Reopen only on a newly measured bottleneck (e.g. genuinely direct-ring wide attention, or a different resident slot distribution). Four-row NVFP4 weight reuse is evidence for shared rows on synthetic native-format data, **not** for Tideglass W1. Native HIP batch submission lost against our existing native loop independently of prediction accuracy.

**Promotion rule:** follow the [qualification matrix](qualification.md). First hold policy fixed (math, placement, RAM, sequence and sampling). Then run the actual production policy, with naturally evolving tasks that can fail, and report both the winners and failures. For approximate target policies compare *grades/time* against stock, and test identical IDs only where equivalence is claimed: inactive guidance, same-policy reference, rollback and warm extension. Keep a working dense/no-draft fallback. This plan proposes subsequent work; it does not claim any of it is deployed.
