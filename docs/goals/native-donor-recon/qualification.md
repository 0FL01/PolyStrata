# What would justify integrating a result?

**Baseline:** the installed dense-Q8 W1 policy on the RX 6700 XT, not the donor, a frozen cache, an attached but unused drafter, or an approximate KV run. Keep fixed placement and replay for *localizing* changes; qualify with live swaps as well. No production binary or deployment change is part of this report.

## Exact scheduling, layout or data-movement change

1. At identical rows, compare matching arithmetic: FP32 vs FP32 or current H2 vs H2. Compare real intermediates the *next* stage consumes: packed Q8_1 or split `(max,sum,partial)` as well as final FP32, ordered expert IDs/weights/backend and sums; for a copy, the consumer's data and untouched slots. Check cold/hot, partial tile, wrap, seal and stage crossings. For an attention prefill change include a long tool suffix after RESTORE, not just warm single-visit graphs. Do not substitute H2 for the dense FP32 verifier by accident.
2. Same-day control/control then AB/BA, identical model, release options, actual binary hashes, private copies of the same seed, snapshot and same cap; perform this *before* changing funding or allocation policy. Require no first generated-ID difference with identical prompts and greedy settings, including first post-tool token. Check logits and committed state on representative continuation; no-draft path untouched. If control/control diverges in placement, match the maps to localize, and report live nondeterminism separately. Do not cherry-pick the matching pair. Time untraced, profile separately.
3. For deployment use ordinary production memory policy. Measuring 100 MiB freed by a draft buffer is different from spending it on more expert slots (changes arithmetic); use a second experimental arm. Report staging, mapped/charged global KV, committed physical expert count, peak memory and minimum free VRAM. Keep rollback/old session path; no changed format just for a speculative optimization.

## Drafter and verifier

- The restricted list must be built *without* eval trajectories (hash GGUF, tokenizer, list and source). Include task syntax, tool delimiters and multilingual text, check target-token coverage and actual acceptance separately. Score only real ID rows (`output_` Q6_K), remap ties to the lowest real ID. A masked full-head run answers *what is proposed*, not *how fast an indexed kernel runs*. Full-vocab probabilities become too confident if renormalized on a subset; don't feed them unchanged to the current controller. Never use the subset as a target candidate mask, even for greedy verification.
- Measure first and later proposals, target verify W1/W2/… and replay/commit with position, depth, cache residency, recent phase. Compare against an attached W1 control **and** unattached production. For width `1+K`, compare `E[wall_draft+verify+repair+commit] / E[rows_actually_committed]` at that width to serial wall/row; use observed *contiguous-prefix* acceptance by depth. K=0 is a real choice. Calibration must come from held-out, serial-equivalent local runs; the donor's V620 rates and per-batch thresholds do not fit a B1 CPU/GPU engine. Reset/decay at tool boundaries, charge exploration and confidence tests to the measured cost. Wider verification is not an exact optimization merely because the proposer is lossless in theory.
- First prove an authoritative verifier **row by row**: Q6_K reduction and attention chunk order, naturally evolved expert usage/placement and backend, conv rollbacks and DSpark taps. Test different rejected futures with a common accepted prefix. At wrap/growth/reject, compare serial vs speculative continuation, all sampled-from logits/RNG and retained state; savings from a hypothetical perfect oracle or removal of all replay cost are not speedups. Existing [exact-verifier experiments](../2026-11-24-inkling2-dspark-exact-throughput.md) already cover several plausible dead ends. If there is no serial-equivalent verifier with plausible isolated cost, stop before tuning a scheduler for rollout.

## LoopCD is a change to the target

Hidden updates the final partial state as `h₂ + α(h₂ − h₁)` and can separately blend the corresponding deep block states. Preserve which parts of the stack belong to prelude vs core. Skip-Coda Logits is a second **weak** readout, not a skipped strong coda: after softcap compute `m=max(z_strong)`, optional `α_eff=α(1−p_max)`, mask below `m+log β`, otherwise `z=z_strong+α_eff(z_strong−z_weak)`. For α=0 bypass the *whole* transform, including masking. A Q6_K second full head plus synchronization is not free on this card. In an exact greedy-only specialization it is possible to project weak rows only for the strong APC shortlist **after** finding its exact maximum/cutoff (β>0); that's a different candidate than a fixed draft shortlist. Price compacting/synchronizing and handle NaNs/ties, sampled paths and missing IDs explicitly. Not measured as an integrated optimization here.

Donor #210's no-draft suite was **12 direct math + 8 code**, stock checkpoint, V620. Hidden α=.35: 15→16 passed out of 20 (+0.14% B1 ms/token); adaptive Logits α=.25: 15→18/20 but **106.13→108.26 s** suite wall and +13.05% B1 ms/token. With DSpark the shorter-cap B2 suite is **different**: 11→12 Hidden, 11→14 fixed Logits, 11→11 adaptive Logits; fixed Logits took 185.62→207.17 s. Separate B1 DSpark speed sweep 95.44→89.79/73.86 ID/s (Hidden/adaptive Logits). These are neither Tideglass agent grades nor evidence that shorter reasoning or higher acceptance caused the change.

Use the existing [graded production receipts](../2026-11-25-adaptive-global-kv/production.md) as a **task definition**, not as a contemporaneous A/B. Deployed control at 197,021 committed IDs: code/42, reason/42, code/79, reason/79 solved in **19.573 / 28.908 / 25.834 / 27.128 s after RESTORE**, grades **118/118, 4/4, 118/118, 4/4**, natural stops, two useful file reads each. **1/4 by 25 s; 4/4 by 30 s.** A same-ELF stage experiment gained mixed W1 ID/s and matched 97/97 greedy IDs yet lost the reasoning/42 grade. The independent 3,400-ID multi-chunk tool return also caught a continuation failure that a faster W1 metric missed.

Predeclare controls, seeds, tasks, sampling/template, stop/time caps before running a policy; include held-out tasks and failed legs. Start with W1 and baseline dense KV. Check α=0 identity, nonterminal prefill identity and policy-specific SAVE/RESTORE/extend semantics (a prompt-final row can become an interior row at the next tool return). For α>0 compare *grades*, tool calls and arguments, parser errors, retries, useful vs reread tokens, reasoning vs final IDs, natural stop vs truncation and time to correct, with and without startup/RESTORE. Report successes by common wall budgets, not just median time of the winners. Only then compare the accepted guess prefix and grouped verifier under that **same** target. Avoid stacking guidance, sparse KV, expert reassignment and adaptive K in a single uncontrolled comparison.

**Concrete first implementation boundary for Hidden:** keep the last *canonical* checkpoint before the earliest guided terminal/generated row. To reuse a transcript as plain prompt, restore that checkpoint and replay just the affected suffix as nonterminal prefill, then apply guidance to the new scoring row. If no such checkpoint exists, use canonical rebuild as reference, not an ID-keyed cache hit. Measure this cost on a long prefix; a policy tag alone cannot make an old terminal row match a newly interior row even if α didn't change. If experimenting with guided `window()` later, `Engine::keep()` can rerun accepted rows not covered by `snap_tokens()`; those replays must receive exactly the original guided-row mask. Neither the short pilot nor 724 matching enabled-mode tokens checks that case. Keep guidance separate from KV compression/slot funding until the warm path and same-policy rollbacks pass.
