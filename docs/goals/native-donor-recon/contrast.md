**One formatting win is worth testing, but it is not a reasoning or performance result.** The donor's scores and today's native pilot test different models and tasks. The formulas and release gates are in [qualification.md](qualification.md).

### Native quality, state and proposal test

Built an isolated gfx1031 ELF using the existing state bank. Hidden blends the strong partial and internal core block with the previous pass just before visit 42. Logits obtains the weak readout just before the last core restart (visit 30), projects the same Q6_K output head and applies its normal softcap. Strong coda still runs. Compare off, zero (does weak work but does **not** mask/contrast), Hidden α=.35, fixed and adaptive Logits α=.25, β=.1. Short pilot: real Tideglass, Q8_0 KV, context 512, batch 128, diagnostic 3,072 MiB combined budget, 8 workers, no lookup, greedy same prompts/limits. Does not model a production 197K cache or give a general time-to-correct estimate.

- On five short naturally generated fixtures stock/off/zero/fixed/adaptive passed **4/5**, Hidden **5/5**. The difference was emitting exact JSON under the same 140-ID budget. Python, ordering logic, the declared `catalog.find` call and the separately prompted tool-result continuation passed in every arm. This screen itself had stock/off ID drift. On the frozen three-tool-fixture repeat, off/off/zero matched all **257 IDs**. Hidden again completed strict JSON at 93 IDs (first changed output **5**), adaptive answered at the 140-ID cap (first change **7**); fixed truncated and off stayed in reasoning. All arms emitted the **same 62 greedy IDs** for the actual declared-tool fixture. None of these five short fixtures executed an external tool as part of the same generation. On the two ordinary tool fixtures no-draft decode in ms/ID: off **34.43/34.69**, off-repeat **34.96/35.48**, Hidden **35.14/34.87**, fixed **36.22/37.22**, adaptive **35.83/36.46**. Single-process legs, not a speed qualification.
- A native SAVE after 68 identical prompt IDs, before feeding the first generated ID, isolated the state change. Hidden changed **only** the new coda KV row and convolution state at visits **42–47**. In physical layers 19, 21, 22 and 23, one expert ID changed per layer. The emitted ID didn't change. Off/off and off/adaptive Logits matched the entire saved byte stream and expert counts. Thus Hidden's old terminal state cannot silently become an ordinary interior row in a differently configured session. Logits does not directly alter state at this tested identical history; a subsequent changed token will.
- With the production-format DSpark attached, three proposals, frozen short fixtures, native `keep()` and live window scheduling: `DONE` reported **141/165** matched/offered off, **122/146** Hidden, **147/185** fixed, **144/160** adaptive. Not counts of all committed extras and not equal trajectories. All **724** enabled-mode IDs matched their own serial targets in this sample. **Off-live itself first differed at output 97** on strict JSON, so these are not verifier-exactness receipts. On a *common* 62-ID declared-tool trajectory, Hidden changed **2/61** oracle proposal tuples and Logits changed **0/61**. Coda output feeds the drafter; the three pre-coda taps alone do not fix its proposals. Do not fit K from the pooled acceptance alone.

### A cheaper weak readout specific to Skip-Coda Logits

The second active Q6_K head reads up to **378 MB** of weights per scored row, not counting cache. But for β>0 the strong distribution determines the APC survivors *before the weak scores are known*. Compute the true strong maximum and, in adaptive mode, full-vocabulary denominator; compact the global IDs meeting `z ≥ max(z)+log β`; project **only those weak rows** and fill every other output with `−inf`. This is an exact algebraic elimination for the **APC target policy**, not an approximate restricted *draft* vocabulary. Cap the fast path, not the answer: use a dense fallback on overflow, β=0 or unsupported layouts. α=0 bypasses all guidance/masking. Preserve sampler penalties, RNG and target/weak softcap/reduction semantics.

`apc_screen.py` looked at **229** real post-softcap strong rows from earlier native Tideglass runs, before enabling any contrast. Code/reasoning HTTP at 64K, short sampled history at 2K, mixed/code W1 at 64K. β=.1 left **1 ID in 196 rows**, 2 in 17, 3 in 10, 4 in 4, and 7 and 11 in one each. At β=.01 the maximum was **24** (one row above 16). At β=.1, up to **21.3% of the probability mass** was outside the list: recomputing adaptive `p_max` *from the list* would be wrong. A top-1 strong mask leaves no choice for a plain greedy argmax; it doesn't imply full FP32 logit values, logprobs or arbitrary downstream samplers can ignore weak scores. Strong/weak history will change once the intervention changes tokens; these are feasibility counts, not survival frequencies on all active workloads.

**GPU proof, including a better baseline.** On gfx1031 the device marked survivors in sorted global-ID order within 256-row tiles, projected the weak Q6_K rows without a host count/readback, applied the **stock** weak softcap and produced a full FP32 vector (`−inf` outside the mask). Adaptive `p_max` used all strong rows. An initial fused cap/apply differed by one ULP and was rejected. Final indexed vs full weak: **all 200,058 logits bit-identical in 13 checks**, including archived strong rows with 1/4/11 survivors, inclusive/exclusive cutoff neighbors, tied maxima/lowest ID, α=0 and β=0; 218 selected raw and capped weak scores also matched. True GGUF weights, surrogate weak inputs, finite strong inputs only. This proves a leaf relative to native dense APC, not a sampled trajectory or donor framework parity.
