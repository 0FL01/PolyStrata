### Where an improvement would appear

The live reference is dense Q8 + compact SWA with whole-expert funding (`35c899cb`, no drafter), **not** the faster opt-in K256/V4 mode. See the [deployed task results](../2026-11-25-adaptive-global-kv/production.md). 24 weight layers, **48** separate logical visits (prelude 0–5, core 6–17 three times, coda 18–23); 40 local and eight full attention states. Restarting the core uses prelude + new message banks. Use visit, not just physical layer, to name a KV/conv boundary and measure exposure. Current W1 dual-write publishes real router logits and normalized input together; routed GPU slot kernels and the CPU group start once the host routes. The fused tail reads the mapped CPU result. There is no general-purpose CPU-expert-result H2D to delete. The inherited host pool's physical `+1` lookahead is gated by `!looped_`. The existing `STRATA_INKLING_PREFETCH` is prompt overlap.

**New end-to-end reference, not a service benchmark:** RX 6700 XT + Ryzen 7 5700X, Release `aa3aab2d…`, Tideglass v2.1 GGUF `7af63a2c…`, 8 workers, live swaps, 2,048 mixed prompt + 24 greedy steps, no drafter, fixed 4,968 MiB total expert/KV budget to reproduce initial placement (1,143 startup slots), 2 GiB reserve. `baseline_run.py` then `profiler/collect.py` under the updated guard. Traced/untraced **25/25** IDs match. Wall **54.00 / 51.99 ms/token**, untraced **19.23 ID/s**. From trace: GPU kernels **16.49**, copies **6.62**, overlap **2.75**, neither **33.64 ms/token**. Synchronization can overlap other threads and device work. Do **not** call 33.64 ms idle CPU expert latency or add kernel/copy/sync spans. Largest kernel categories were other projections **5.57**, Q4_0 experts **4.15**, norm/quant/mix **1.57**, attention **1.22**, LM head **1.15 ms/token**. Even the short *code* W1 control is a different prompt and longer sample. Near 197K, the historical same-ELF 404-input trace spent **10.92 ms/token** in the eight dense global attentions; a short-code optimization can miss this regime entirely.

### Cache and verifier invariants for a later port

- A projected next-router top four on a previous hidden row is not the true normalized destination row. Only unmodified `Inkling2::route` chooses IDs using sigmoid+bias and normalizes the **unbiased** selected scores. For an exact path preserve ordering, weights, CPU/GPU assignment and accumulation. For asynchronous DMA retain source/destination generations, pending ownership and stream ordering until the *last* consumer; false hints neither evict demanded bytes nor advance policy observations. Do not retry an uncertain partially submitted batch. Working-set expansion must not spend the free-VRAM reserve or silently change how many model experts fit.
- `main.cpp` commits contiguous accepts; the last shown EOS/length token is not fed. Measure `1 + actually_committed_extras`, not all correct proposals or the printed `guessed_right`. At each row verify real history/RNG and transformed logits. Include reject first/middle, all accepted, bonus/terminal, cancel→rewind→overwrite, prompt extension and repeated SAVE/RESTORE. Check all 48 chronological KV/conv states and accepted-only draft context/taps, compact SWA wrap, global growth and seal/index boundaries. One-pass placement/follower state across W>1 is not serial W1; K256 is serial-only. A byte-exact draft or one ID-matching run cannot certify the verifier.
- `Hidden` changes coda KV/conv. A row decoded with one policy can later be part of a cached prompt with another; use proven canonical replay/phase semantics or invalidate affected state with a policy-specific identity. For Logits, keep the weak readout nonmutating; apply strong/weak softcaps, plausibility filter and contrast at the same first-token/serial/verify boundaries. Rank actual parsed tool actions, grade, reasoning length, terminal reason and time to correct (including tool results and unsuccessful attempts); only compare DSpark acceptance **within** the same target policy. Preserve no-draft W1 and alpha=0 by construction.
