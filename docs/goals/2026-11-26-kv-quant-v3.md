## Data: what the cached history actually looks like

One guarded prefill of the archived 197,135-row coding prompt captured the normed post-convolution FP32 K and V of
every row at all 8 full-attention visits (13 GB), plus Q, relative query, sink, gate and the GPU output at every 64th
row and 28 greedy decode rows. Dense Q8 SAVEs were written at 65,796 / 129,015 / 194,973 / 197,021 rows, the cuts
of the earlier archived snapshots (all long task prompts are nested prefixes of this history). Checks:

- The CPU replay of the captured rows reproduces the GPU attention output to gated relative L2 1.7-3.9e-4 (the
  flash prompt reader's half-precision noise) at all 8 visits.
- NumPy Q8_0 of the captured FP32 rows equals the codes in the engine's SAVE **bit for bit** (0 mismatches in
  8 x 63,744 rows); an identity fixture written by the CPU tool is byte-identical to the engine SAVE.

Distribution facts (64K, all visits; `lab/dist-64k.json`):

- **Every V row has norm exactly sqrt(128)** (11.3137; V is RMS-normed without a weight). A per-row or per-block V
  scale carries almost no information.
- **91-99.5% of K rows sit exactly at the norm clip** (22.627).
- Native V kurtosis 3.9-12.8 (coda visit 47 is the heaviest); after a signed WHT128 2.79-2.96, after plain H32
  ~2.98. Rotated V coordinates: std 1.0000, kurtosis 2.90, max 4.68. Block-32 crest p99 falls 4.3-5.5 -> 3.3.
- Per-(visit, head) mean vectors: up to 69% of one V head's energy (visit 11/23/35 head 4), 6-23% pooled over heads
  (page mean 7-29%). K means carry 15-44%.
- An empirical Lloyd-Max codebook equals the Gaussian one within 0.02 dB: no model-specific table is needed.
- Same physical layer, different pass: V cosine 0.47-0.71, held-out linear R^2 0.1-0.58. Cross-visit prediction
  (AQUA-KV style) would need a second cache read per visit; not pursued.

## V codecs at equal bytes (64K, V only)

Metric: production K (Q8) and attention weights are unchanged; rows below the page-aligned seal (pos - 2048) use the
codec, the newest rows stay Q8. Error = gated relative L2 of the attention output against the dense Q8 output, p95
over 59 real queries x 24 heads per visit, averaged over the 8 visits. The Q8-vs-FP32 floor is 0.004-0.009.
Bytes are per row and KV head including all scales/metadata.

| Codec | B | bpv | rec. rel. L2 | att p95 | worst-visit p95 |
| --- | ---: | ---: | ---: | ---: | ---: |
| current V4 refit (±7, fp16/32) | 72 | 4.50 | 0.114 | 0.0607 | 0.094 |
| q4_0 | 72 | 4.50 | 0.100 | 0.0524 | 0.079 |
| q4_0 + WHT64 (previous quality fixture) | 72 | 4.50 | 0.085 | 0.0446 | 0.070 |
| IQ4_NL + WHT128 | 72 | 4.50 | 0.081 | 0.0459 | 0.075 |
| ExLlama H32 linear / cubic 4 | 72 | 4.50 | 0.089 / 0.082 | 0.0458 / 0.0430 | 0.073 / 0.067 |
| TurboQuant turbo4 / Octave 4 | 66 | 4.12 | 0.095 | 0.0506 / 0.0507 | 0.076 / 0.081 |
| **LM4 known-norm, no metadata** | **64** | 4.00 | 0.095 | 0.0506 | 0.077 |
| uniform 4 known-norm | 64 | 4.00 | 0.105 | 0.0593 | 0.085 |
| LM4 + page mean (LS scale) | 68 | 4.25 | 0.082 | 0.0422 | 0.063 |
| **LM5 known-norm** | **80** | 5.00 | 0.049 | 0.0256 | 0.038 |
| uniform 5 known-norm | 80 | 5.00 | 0.057 | 0.0307 | 0.044 |
| turbo5 / ExLlama linear 5 | 82 / 88 | 5.1 / 5.5 | 0.049 / 0.043 | 0.0256 / 0.0223 | 0.038 / 0.033 |
| **LM6 known-norm** | **96** | 6.00 | 0.025 | 0.0135 | 0.018 |
| uniform 6 known-norm | 96 | 6.00 | 0.031 | 0.0165 | 0.024 |
| turbo6 / ExLlama linear 6 | 98 / 104 | 6.1 / 6.5 | 0.025 / 0.021 | 0.0133 / 0.0113 | 0.019 / 0.017 |
| native Q8_0 | 136 | 8.50 | 0.006 | 0 | 0 |

- Bits decide: each extra bit halves the error. At equal bits the good methods differ by 10-20%.
- With known norm, a fixed Gaussian Lloyd-Max codebook in the WHT128 basis needs **no stored scale** and matches
  TurboQuant's norm-corrected fp16 scale exactly (the correction can be computed from the codes). It is smaller than
  the current V4 and more accurate.
- Uniform codes cost 0.76 / 1.31 / 1.63 dB at 4 / 5 / 6 bits (about 20% more attention error than LM).
- **Double quantization is nearly free**: coding from the stored Q8 instead of FP32 raises LM6's error against FP32
  from 2.54% to 2.62% and leaves attention p95 unchanged. A native seal can stay on the Q8 hot ring.
- Mixed precision by importance: keeping the 0.2% most-attended cold rows (chosen from earlier queries, scored on
  later ones) native costs ~0.1-0.15 B/row and cuts att p50 by 5-37% (most at coda visit 47); keeping page 0 native
  alone gives 5-20%. Returns fall off quickly beyond 0.5%.

| K codec | B | att p95 | attention top-1 row kept |
| --- | ---: | ---: | ---: |
| q4 g32 / LM4 / LM4 + page mean | 72 / 66 / 68 | 0.143 / 0.117 / 0.091 | 85-90% |

| q6 g32 / LM6 / LM6 + page mean | 104 / 98 / 100 | 0.031 / 0.031 / 0.024 | 96-97% |

K needs about one bit more than V for the same output error. An 8-bit log scale hurts K (its norm is not fixed for
every row); the page mean is worth ~25%. K6+mean / V6 combined is about V5-level error. K4 is out.

## Does attention error reach the answers?

**Teacher-forced logits.** Each arm restores its SAVE (only cold global V changed, re-quantized to Q8 for the dense
reader), then the recorded three-turn agent output is forced with every step's top-256 logits and LSE logged
(538/612 positions at 64K, 421/599 at 197K; fixed 5,200 MiB cap, zero swaps). Restoring the control twice gives KL
exactly 0. Mean KL(control || arm) in nats/token:

| Arm | 64K coding | 64K reasoning | 197K coding | 197K reasoning |
| --- | ---: | ---: | ---: | ---: |
| **jitter: FP32 V + N(0, 0.002), +0.35% error** | 0.0086 | 0.0064 | 0.0035 | 0.0135 |
| jitter N(0, 0.02) | 0.0071 | 0.0074 | | |
| V4 refit | 0.0063 | 0.0073 | 0.0039 | 0.0079 |
| q4_0+WHT64 | 0.0048 | 0.0061 | | |
| LM4 | 0.0067 | 0.0062 | | |
| uniform 4 | | | 0.0062 | 0.0111 |
| LM5 | 0.0062 | 0.0083 | | |
| uniform 6 | | | 0.0045 | 0.0069 |
| LM6 | 0.0072 | 0.0044 | 0.0079 | 0.0127 |

A perturbation 30x smaller than V4's produces the same distribution shift. Any nonzero change to the history moves
the logits by a fixed amount, almost all of it at the few high-entropy positions; median KL is ~0 for every arm. On
these continuations teacher-forced KL cannot rank V4 to V6, and a single free-running pair says nothing about a
codec: every arm, including the jitter control, leaves the control's trajectory.

**Free-running graded tasks, 64K** (restore 65,796 rows, original prompt, T=1/top_p=1/top_k=0, original turn caps,
allowlisted `read_case` fixtures and graders; 2 tasks x 6 seeds per arm, fixed placement):

With n = 12 the binomial standard error is ~0.13; the pure-perturbation control falls exactly where V4 does. No arm
shows longer reasoning outside the spread of the controls.

| --- | ---: | ---: | ---: | ---: | ---: |

Again the pure perturbation scores best and the most accurate codec (LM6) lands below uniform 4: the ranking is

## Native reader on gfx1031

`rdna2-rnd/kvq-v3/vread.hip` reproduces the production W1 decode reader's geometry (eight waves per block, one KV
group per wave, lane = 16 dims x one of four keys, two key steps unrolled, FP32 online softmax, relative bias, sink,
gate, 160-chunk split) with native Q8 K and V packed in the WHT128 basis. The PV sum stays in the rotated basis; the
combine applies one inverse signed WHT128 per head before the gate. Uniform codes are `v_cvt_f32_ubyteN` of the code
with the offset and step folded into the combine; LM codes use a 64-entry LDS table; P4 uses two `v_perm_b32` per
four codes. All seven variants match a double-precision CPU oracle to 1-2e-6. No spills; 157-160 VGPRs (Q8: 172).
Key-loop VALU per iteration: Q8 709, U4 705, U5 719, U6 757, LDS-LM5 743, LDS-LM6 781, P4 733.

Decode plus combine, one row, read-flushed 256 MiB, median of 15, two runs agree within 0.5%:

| V | B | 65,536 | 131,072 | 199,070 rows | vs Q8 at 199K |
| --- | ---: | ---: | ---: | ---: | ---: |
| Q8 (production) | 136 | 0.460 ms | 0.885 | 1.338 | |
| uniform 4 | 64 | 0.384 | 0.726 | 1.065 | -20% |
| LM4 via v_perm | 64 | 0.397 | 0.749 | 1.097 | -18% |
| uniform 5 | 80 | 0.430 | 0.814 | 1.195 | -11% |
| uniform 6 | 96 | 0.431 | 0.812 | 1.203 | -10% |
| LM5 via LDS | 80 | 0.449 | 0.850 | 1.242 | -7% |
| LM6 via LDS | 96 | 0.441 | 0.829 | 1.224 | -9% |

The production reader moves ~330 GB/s at these spans, so fewer bytes pay directly. The 5-bit format is no faster
than 6-bit (its extra 2-byte plane load is nearly free): 5 bits only buy VRAM. LM6 through LDS costs 1.7% over
uniform 6 for 1.6 dB less error.

A rotation-free V6 (symmetric int6, fp16 scale per 32, 104 B) would plug into the existing native-basis readers:
its mean attention p95 is 0.0141 (LM6 0.0129, uniform 6 0.0163) but its worst head reaches 0.101 against LM6's
0.049 (outlier channels at visit 5). Rotation is what protects the tail.

## What freed VRAM is worth

Dense Q8 W1, the same forced 421-ID three-turn 197K coding continuation, zero swaps, stable prefill. A 5,700 MiB
combined expert/KV cap is already the physical limit at this length (6,000 MiB gives the same placement), so
5,200 vs 5,700 MiB removes exactly V6's 499 MB saving: 436 experts after RESTORE and 31.8% of routed picks on the GPU
vs 34.0-34.9%. Identical work measured 11.5-17.7 IDs/s across eight interleaved runs: each RESTORE reads a 3.5 GB
SAVE and pushes part of the 15.5 GB GGUF out of the page cache on this 31 GB host. The two quiet adjacent pairs gave
17.00 -> 17.38 and 17.42 -> 17.70 IDs/s, **+1.6-2.2% for +499 MB of experts**. Global attention is ~10.7 ms of a
~58 ms token at this length; the reader table above saves 1.1 ms (V6) to 2.2 ms (U4).

Estimate for a native cold-V format at 197K, before any integration overhead: **V6 ~+4% decode, U4 ~+6-7%**, at
64K essentially nothing (V6 frees 168 MB there). Speculative verification amortizes KV bytes over the window and the
prompt reader is compute-bound, so neither is expected to add much. This is a capacity tool with a small speed
benefit on this host, not a large decode lever; CPU experts dominate long-context decode (~68% of picks on the CPU).

## Recommendation and integration plan

1. Keep dense Q8 global KV and exact compact SWA as the default. Do not ship the current V4 refit: it is the least
   accurate equal-byte codec and the only arm with a (weak) quality signal.
2. If long-context capacity or the ~4% at >=128K is wanted, the format to build is **V6R**: signed-WHT128 basis,
   Gaussian Lloyd-Max 6-bit codes (or uniform 6 for the cheapest reader), no stored scale (V norm is exactly
   sqrt(128)), nibble plane 512 B/row + two bit planes 256 B/row, 768 B/row vs 1,088 B native (-29% V, -15% KV).
   Page 0 stays native. K stays Q8; K6+page-mean would be the next step only with a much larger quality run.
3. Reuse the V4 hybrid machinery: the Q8 hot ring, page seal, VMM cover/funding, compact SAVE import/export. Change
   the seal kernel (dequant Q8 -> WHT128 -> codes; double quantization measured as free), the cold plane widths, the
   decode reader (cold chunks accumulate in the rotated basis; launch cold and hot ranges as separate chunk sets so no
   chunk mixes bases) and the combine (inverse WHT128 of the cold partial sum per head, then add hot, then gate).
   The prompt reader needs the same split (cold partial, hot partial, rotated combine); the W1/verifier partition must
   stay identical for exact verification.
4. Gates before promotion: seal/RESTORE/STOP/append parity against same-codec W1, verifier parity, read-flushed W1
   and W4 timings at 64K/128K/197K, prompt TTFT after 114-row and 2K-row returns, and a graded run large enough to
   bound a quality loss (~200 runs per arm), with the page cache pinned (`cat` the GGUF before each timed leg).

## Host incident: intermittent storage corruption

During the runs the kernel logged Btrfs `csum failed` / `direct IO failed` on a valid engine SAVE (cold V codes,
visit 17) and the engine rejected another valid fixture with `payload checksum mismatch`; the same bytes read
correctly before and after. The device counter shows `corrupt 886`, with events on 24-26 November, which likely
explains the unexplained 199K RESTORE checksum refusal in Venture V2. The engine's payload checksum turns such reads
into a refused RESTORE, never silent use; the harness retries those cells. After the reboot all 25 GB of SAVEs read
cleanly with O_DIRECT. RAM/NVMe checks are recommended before trusting long runs on this host.

## Failed or closed hypotheses

- Teacher-forced KL / NLL as a codec ranking: dominated by the perturbation floor (any change, even +0.35% V
  error, gives the same shift).
- Model-specific (empirical) codebooks: equal to Gaussian Lloyd-Max within 0.02 dB.
- Cross-pass prediction of V (AQUA-KV style): R^2 0.1-0.58 and a second cache read per visit.
- KVarN-style dual scaling on 128x128 V pages: no gain over a known-norm Lloyd-Max code at equal bytes (V is
  already variance-normalized per row); page mean helps 15-20% for V, ~25% for K.
- 5-bit V as a speed format: no faster than 6-bit in the native reader.
- 8-bit log scales for K; K4 in any form.
- Reproducing old snapshots bit for bit: the rebuilt 64K SAVE has the archived size but a different hash (different
  binary/placement); all comparisons here use the new snapshots and their own controls.
