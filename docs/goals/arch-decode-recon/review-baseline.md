**Четыре пары завершены; кандидат не тестировался.** RX 6700 XT, Ryzen 7 5700X, Tideglass Inkling, 2048 входных ID. Проверены сырые `metrics.json`, `config.json`, engine logs, telemetry и guard всех девяти ног. SHA-256 бинарника, конфига, prompt CSV и seed совпадают с первым `mixed-2048`; параметры движка совпадают, кроме приватных путей `HOME` и profile. Каждый запрос — первый в новом процессе, без трассы. Warmup **42.99 t/s** исключён из пар. Для восьми последующих ног медиана **42.61 t/s**, диапазон **41.96–43.02 t/s**, выборочное SD **0.32 t/s**; `256 / (последний − первый приход ID)`. Разница этого окна и `DONE.decode_ms` не превышала 0.15 ms.

Одинаковый знак в этом блоке — наблюдение на одинаковом движке, а не выигрыш. Эффект порядка 1–1.6% эта серия не отделяет от шума; 1.62% — не верхняя граница и не порог PASS. Для квалификации нужны новые парные проверки в целевых условиях; четыре пары не дают надёжной оценки хвоста шума.
- **ID, placement и guard:** все девять ног дали 256 шагов и ровно те же 257 greedy ID, что и первый `mixed-2048`; `finish=length`, прочитаны все 2048 prompt ID, reuse/drafts нулевые. На старте каждой ноги 1176/3072 экспертов в VRAM, против 1171/3072 в первом запуске; не было строк о resize. Во всех девяти ногах счётчики запроса одинаковы (79978/98688; в первом 79779/98688), выходные profile совпали побайтно. Это согласуется с одинаковым placement на уровне этих счётчиков, но не доказывает одинаковые slots и upload timing на каждом visit. Минимум sampled VRAM 1998.42 MiB при floor 1536 MiB; `stop-reasons=[]` для всех. Во всех журналах те же 22 предупреждения из истории boot, новых во время ног нет.
- **Хост не был полностью тихим:** параллельный CPU RECON продолжался. По 24 точкам внутри измеряемых decode-окон (три на ногу, шаг около 2 s): loadavg за минуту 5.14–6.34; PSI `some avg10`: CPU 0.15–0.49%, I/O 0–1.87%, memory 0%. CPU policy clocks 1.74–4.65 GHz, CPU `temp1` 66–75 °C. Во всех этих точках GPU DPM отмечал 2400/1000 MHz (core/memory), три термодатчика GPU — 58–63 / 65–70 / 64–68 °C, `gpu_busy_percent` 64–94%. Это грубые снимки, не непрерывные clocks/busy time; причину разброса по ним не установить.
- **Сопоставление с первым 2K:** первое окно, пересчитанное по тому же знаменателю, — **32.86 t/s** (7790.87 ms против медианы после warmup 6007.87 ms); медианы шага сопоставимы (22.64 ms против 22.28–22.81 ms). Три выброса в первом запуске суммарно 1774.02 ms; медианы шагов на тех же позициях в восьми повторах суммарно 71.96 ms. Разница этих трёх интервалов арифметически даёт 1.70 из 1.78 s различия окон. В повторах только один шаг >100 ms (`p3-a`, №201: 133.86 ms); p99 по ногам 36.66–40.73 ms против 146.47 ms. Первый запуск также отличался временем загрузки (7.6 против 1.5–1.7 s), prefill (4356 против 2141–2200 ms) и стартовой ёмкостью кеша. Причина выбросов неизвестна: первый запуск и серия после warmup — разные наблюдения, не контролируемое сравнение cold/warm. Все интервалы оставлены в расчётах.

## Рекомендации первичного аудита

1. **Один интервал для числителя и знаменателя.** Для pipe E2E сделать основным `decode_wall_ns = ts[-1] - ts[0]`, `decode_t_s = 1e9 * (len(ts)-1) / decode_wall_ns`; сохранить исходные timestamps, `engine_decode_ms` из `DONE` и разницу отдельно. Arrival quantiles отражают flush/pipe/scheduling клиента, не время ядер. Если нужен engine-side контроль, снимать `steady_clock` непосредственно после первого и последнего `fflush(stdout)` в отдельном экспериментальном режиме, без пер-токенной печати таймеров и без смены `DONE`. Принимать только `steps+1` строк `T`, `finish=length`, zero accepted/offered, `RESUME=0`, `DONE.reused=0`, `DONE.read=length`, положительный wall; EOS/cancel/короткую серию хранить отдельно, не смешивать. Проверять `READY` context вместо одной константы в harness. В `c74109e8` укороченная серия от трёх ID могла пройти, а `--steps 1` не поддерживался проверкой/квантилями.
2. **Выделить trace в отдельный режим.** `c74109e8` не читает `STRATA_VISIT_TRACE` в движке; harness всё же копирует ключ из окружения, и `cfg['env']` может включить другую диагностику. Timing должен явно запрещать trace env/wrappers (включая profiler/`LD_PRELOAD`); в metadata записывать режим и фактические argv/env. Проверить overhead отдельно на одной и той же trace-capable сборке OFF/ON, с той же длиной, ID и seed; сверять greedy и placement. Hooks, вывод и profiler могут сдвинуть асинхронные upload completions, которые `follow()` замечает через `cudaEventQuery`; одинаковый seed не гарантирует одинаковой траектории. Не добавлять sync в измеряемый путь ради трассы; GPU busy считать по объединению интервалов, не сумме перекрывающихся spans. Traced timings — только диагностика, не E2E proof.
3. **Сначала quiet live A/A при 2K.** Одинаковые pinned binary/model/runtime, сохранённый CSV, копия неизменного seed в новый процесс на каждую ногу. Зафиксировать политику warmup/кэша страниц и одинаковый thermal/clock старт; отдельно маркировать first answer и warmed traffic. Записывать start/end и низкочастотные счётчики нагрузки CPU/PSI/page faults/I/O, clocks/температуры CPU/GPU, sampled free VRAM, effective slots и доступные decode placement counters. Сделать ≥4 последовательные пары с балансом порядка и одинаковым guard; показывать paired deltas/dispersion и все хвосты, не считать 256 токенов за 256 независимых повторов. Сравнивать все greedy ID и отмечать первый различившийся индекс и position. Отдельный matched-placement/frozen контроль полезен для parity, но не заменяет live A/A; freeze может помешать `cover()` освободить VRAM на длинном контексте.
4. **Воспроизводимая long-context матрица.** Разрешить `--prompt-csv` с ожидаемым хэшем и записывать digest модели/токенизатора и сборки. Оставить tiled fixture для stress отдельно; для сравнений закрепить нерепетитивные prose/code/reasoning/tool fixtures с одинаковым хвостом запроса и независимыми holdouts. Пары сравнивать внутри одной длины (128K и near-cap отдельно), регистрировать изменение placement при росте KV; `SAVE`/повторное использование snapshot делать отдельным режимом с проверкой `SAVED`/`RESTORED` position, не размечать их как cold prefill. Не менять guard ради завершения ноги.
